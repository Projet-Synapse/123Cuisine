// 🎯 1. Résumé exécutif

L'application est déjà dans un état soigné : mode cuisine, tri/recherche/filtres sur les recettes, ajout rapide au clavier, tout-cocher sur les listes de courses, recherche de vrais produits (Open Food Facts), tooltips accessibles sur toutes les icônes, ajustement des portions avec réinitialisation contextuelle, thème et apparence très personnalisables, app desktop avec mise à jour manuelle soignée. Beaucoup des demandes classiques d'ergonomie ont déjà été traitées lors des derniers commits (`7840d0a`, `9464e5d`).

Deux catégories de constats ressortent de cette relecture :

1. Une **anomalie fonctionnelle** (pas juste un défaut d'ergonomie) qui touche directement l'objectif n°1 du projet (éviter les achats impulsifs / listes de courses fiables) : les quantités ajoutées à une liste de courses depuis une recette ignorent l'ajustement des portions.
2. Une vingtaine de **pistes d'ergonomie/productivité**, classées ci-dessous par impact perçu et effort estimé, avec fichier:ligne à chaque fois pour retrouver le code concerné.

// 👍 2. Ce qui fonctionne déjà bien (à ne pas casser)

- `components/IconAction.tsx` : tooltips accessibles (survol desktop, appui long mobile) sur toutes les icônes seules — bon réflexe déjà généralisé.
- `utils/servings.ts` + `app/(recettes)/recipe/[id].tsx:264-305` : stepper de portions avec recalcul des quantités et bouton de réinitialisation contextuel.
- `app/(tabs)/recipes.tsx` : recherche, filtres (difficulté/favoris), tri combinés, avec chip « Réinitialiser » qui n'apparaît que si un filtre est actif.
- `services/courses/openFoodFactsService.ts` : autocomplétion de vrais produits (marque, catégorie, image) à l'ajout d'un article de liste.
- `components/CookMode.tsx` : mode cuisine dédié, étape par étape, texte agrandi.
- Electron (`electron/main.js`) : aperçu avant impression reconstruit maison, confirmation de fermeture, mise à jour manuelle avec filet de secours — signe d'une vraie attention portée au desktop.
- `app/(tabs)/categories.tsx` : réordonnancement des recettes à l'intérieur d'une catégorie (▲/▼ + appui long haut/bas) déjà implémenté et bien pensé.

// 🐛 3. Anomalie fonctionnelle prioritaire

### Les quantités ajoutées à une liste de courses ignorent l'ajustement des portions

**Fichiers** : `contexts/KitchenContext.tsx:354-375` (`addRecipeToList`) appelé depuis `app/(recettes)/recipe/[id].tsx:172`, `app/(tabs)/recipes.tsx:232`, `app/(categories)/categorie/[id].tsx:150`, `app/(profil)/profile/[id].tsx:182`.

Sur la fiche recette, l'utilisateur peut ajuster le nombre de portions (`servingsCount`, `recipe/[id].tsx:45`) : les quantités affichées à l'écran sont recalculées (`servingsFactor`, ligne 51). Mais le bouton « Ajouter à une liste » transmet l'objet `recipe` d'origine, non ajusté — `addRecipeToList` reprend `ing.quantity` tel quel (`KitchenContext.tsx:358`). Résultat : un utilisateur qui double une recette pour 8 personnes avant de l'ajouter aux courses se retrouve avec les quantités pour 4 personnes sur sa liste, sans aucun avertissement.

C'est exactement le genre de problème que l'app est censée éviter (achats impulsifs / mal calculés, cf. l'intention du projet dans CLAUDE.md). C'est aussi la seule fonction d'ajout à une liste dans toute l'app (recette seule, recettes d'une catégorie entière, recette du profil public d'un tiers) : le bug se propage à 4 points d'entrée.

**Suggestion** : faire porter le facteur d'échelle jusqu'à `addRecipeToList` — soit en passant les ingrédients déjà recalculés (`recipe.ingredients.map(i => ({...i, quantity: scaleQuantity(i.quantity, servingsFactor)}))`) depuis chaque appelant, soit en donnant à `addRecipeToList` un paramètre `servingsFactor` optionnel appliqué en interne avec `scaleQuantity` (déjà disponible dans `utils/servings.ts`).
**Effort** : faible (une fonction pure déjà écrite, à appliquer à 4 points d'appel).

// 📋 4. Pistes d'amélioration — triées par impact / effort

// 4.1 🍽️ Recettes & mode cuisine

**Autocomplétion des ingrédients à la création de recette** (impact fort, effort moyen)
`app/(recettes)/create-recipe.tsx:366-431`, `edit-recipe/[id].tsx:380-439`. Ajouter un ingrédient = 3 champs + 1 tap, sans autocomplétion, contrairement à l'ajout d'article de liste de courses qui bénéficie déjà d'Open Food Facts (`create-list.tsx`, `list/[id].tsx`). Pour une recette de 10-15 ingrédients, ça représente un nombre d'interactions élevé. → réutiliser le même composant de recherche/suggestion pour préremplir nom + unité.

**Confirmation avant de perdre un formulaire non enregistré** (impact fort, effort moyen)
`create-recipe.tsx`, `edit-recipe/[id].tsx`, et côté catégories `create-categorie.tsx`, `edit-categorie/[id].tsx` : aucune de ces créations/éditions ne demande confirmation avant un retour arrière qui efface la saisie (photo, ingrédients, étapes compris pour les recettes). → ajouter une alerte de confirmation quand le formulaire a été modifié (`isDirty`).

**Partage d'une recette ou d'une liste de courses** (impact fort, effort faible à moyen)
`recipe/[id].tsx:196-243`, `list/[id].tsx:326-355` : seule l'impression existe, pas de partage natif (texte/lien) alors que le module social (abonnements, recettes publiques) existe déjà. → bouton « Partager » via `Share.share()`/`expo-sharing`.

**Sélecteur d'unité avec recherche** (impact fort, effort faible)
Chips d'unités en `ScrollView horizontal` sans recherche (`create-recipe.tsx:400-424`, `edit-recipe/[id].tsx:414-432`) : ralentit la saisie répétée à chaque ingrédient si la liste s'allonge. → picker avec recherche au-delà d'un certain nombre d'unités, garder les chips seulement pour les plus fréquentes.

**Filtre par tag dans la recherche de recettes** (impact moyen, effort faible)
`app/(tabs)/recipes.tsx:106-119` : les tags (`RECIPE_TAGS`) existent à la création mais aucun filtre par tag n'est proposé en recherche — seule la recherche texte peut les retrouver, de façon peu fiable. → chips de filtre par tag, multi-sélection, à côté du filtre difficulté déjà en place.

**Mode cuisine : minuteur et écran maintenu allumé** (impact moyen, effort moyen)
`components/CookMode.tsx:28-145` : pas de `expo-keep-awake` (l'écran se verrouille pendant une étape longue, mains occupées) ni de minuteur par étape. → activer keep-awake à l'ouverture du mode, détecter une durée dans le texte d'une étape (regex, à la manière de `parseLeadingQuantity`) pour proposer un minuteur en un tap.

**Mode cuisine : navigation directe entre étapes** (impact moyen, effort faible)
`CookMode.tsx:91-101` : les points de progression sont uniquement visuels, pas cliquables — revenir de l'étape 8 à l'étape 2 impose 6 taps sur « Précédent ». → rendre les points tapables.

**Mode cuisine : stepper de portions absent** (impact moyen, effort moyen)
`CookMode.tsx:22-26,63-74` reçoit des ingrédients déjà mis à l'échelle mais n'offre aucun contrôle pour ajuster les portions une fois en plein écran — il faut fermer le mode cuisine, changer le stepper sur la fiche recette, puis rouvrir. → exposer le même stepper +/- directement dans l'écran ingrédients du mode cuisine.

**Swipe-to-delete sur les cartes recette / articles de liste** (impact moyen, effort moyen)
`recipes.tsx:240-319`, `shopping.tsx:56-111`, `list/[id].tsx:679-742` : toutes les actions passent par des icônes toujours visibles (jusqu'à 3 empilées par carte). → geste swipe (`react-native-gesture-handler` `Swipeable`), au moins sur les articles de liste de courses où la suppression est l'action la plus fréquente.

**Zone tactile suppression trop proche du cochage** (impact moyen, effort faible)
`list/[id].tsx:679-742` : le cochage d'un article couvre toute la ligne, avec l'icône de suppression juste à côté (`hitSlop={8}` seulement). Risque réel de mis-tap en cuisine/en magasin, situation où l'on va vite. → agrandir la zone morte ou déplacer la suppression derrière un swipe.

**Scan de code-barres pour ajouter un article** (impact faible à moyen, effort fort)
`create-list.tsx`, `list/[id].tsx` : recherche Open Food Facts uniquement textuelle, alors que l'API supporte la recherche par code-barres et que l'app a déjà l'intégration. → bouton scan caméra à côté de la recherche produit.

**Dictée vocale pour ajouter ingrédients/articles** (impact faible à moyen, effort fort)
Mains occupées en cuisine ou en magasin : aucune reconnaissance vocale n'est proposée pour dicter un ingrédient ou un article.

**Indicateur de connectivité / synchronisation** (impact faible à moyen, effort moyen à fort)
Aucun écran ne signale si les données affichées (recettes publiques, recherche produit, prix) sont à jour ou en cache faute de réseau — situation fréquente en magasin.

// 4.2 🛒 Courses

**`edit-list/[id].tsx` ne permet pas de gérer les articles** (impact moyen, effort faible)
Contrairement à `create-recipe`/`edit-recipe` qui exposent la même UI complète en création et édition, `edit-list/[id].tsx:30-232` ne modifie que nom + supermarché ; pour les articles il faut retourner sur `list/[id].tsx`. → soit retirer le nombre d'articles affiché en lecture seule pour clarifier le rôle de cet écran, soit ajouter un lien direct « Gérer les articles ».

**Changement de supermarché sans avertissement sur les prix/rayons** (impact faible, effort faible)
`edit-list/[id].tsx:68-80` : changer de magasin ne prévient pas que les prix comparés et le tri par rayon seront recalculés.

// 4.3 🗂️ Catégories & dossiers

**Libellés « categorie » non corrigés après le renommage catalogues→catégories** (impact fort, effort faible)
Le dernier commit renomme « catalogues/playlists → catégories » et « groupes → dossiers », mais plusieurs libellés visibles n'ont pas suivi :
- `edit-categorie/[id].tsx:118` → « Modifier le categorie » (devrait être « la catégorie »)
- `categorie/[id].tsx:221` → « Ajouter au categorie »
- `profile/[id].tsx:564` → « Ajouter à un categorie »
- `categories.tsx:409` → fil d'Ariane racine « Catégorie » (singulier) alors que l'onglet est « Catégories »
- `categories.tsx:547` → « Aucun categorie » (accord fautif)
→ passe de relecture ciblée, impact fort car visible à chaque écran clé, effort minime.

**Aucune recherche dans les réglages (« Mon espace »)** (impact fort, effort faible)
`app/(tabs)/compte.tsx:58-108,326-345` : 7 destinations listées verticalement sans recherche ni raccourci, alors que le hub a justement été créé pour regrouper ce qui était éparpillé sur 4 écrans (commentaire du fichier lui-même). → barre de recherche filtrant par libellé + description déjà présents dans `SETTINGS_LINKS`.

**`notifications.tsx` hors du design system des réglages** (impact fort, effort faible)
`app/(parametres)/notifications.tsx:108-116` réimplémente son propre header au lieu d'utiliser `SettingsPage` (`components/settings/SettingsKit.tsx`) : le retour arrière n'a pas le repli automatique vers `/compte` que les 7 autres écrans de réglages ont, et l'apparence diverge légèrement. Risque réel de navigation cassée sur un lien direct (ex. depuis un e-mail de notification) sans pile de navigation. → migrer vers `SettingsPage`/`SettingsSection`/`SettingsCard`.

**Pas de réordonnancement manuel des catégories/dossiers eux-mêmes** (impact fort, effort faible à moyen)
Le réordonnancement (▲/▼ + appui long) existe déjà pour les recettes à l'intérieur d'une catégorie (`categorie/[id].tsx:105-135`) mais pas pour les catégories/dossiers de premier niveau dans `categories.tsx`. → appliquer le même schéma, déjà conçu et testé.

**Pas d'actions groupées (bulk) sur les catégories** (impact fort, effort moyen)
`categories.tsx:263-279,224-245` : suppression et rattachement à un dossier se font une catégorie à la fois. → mode « Sélectionner » (appui long → cases à cocher) pour suppression/affectation groupées.

**Ranger une catégorie dans un dossier reste peu fluide** (impact fort, effort moyen)
`categories.tsx:374-381` : action derrière une icône en bas de carte, sans glisser-déposer possible vers les tuiles dossier visibles dans la même liste. → glisser-déposer catégorie → tuile dossier.

**Pas de recherche transverse dans les dossiers imbriqués** (impact fort, effort moyen)
`categories.tsx:130-153` : retrouver une catégorie rangée profondément impose de descendre niveau par niveau, sans recherche globale. → recherche en tête d'écran qui bascule vers une liste plate tous-dossiers-confondus avec badge du dossier parent.

**Pas de création de dossier à la volée depuis le sélecteur** (impact moyen, effort faible)
`components/DossierPicker.tsx:99-107` : s'il n'existe encore aucun dossier, seul un message d'invite s'affiche — il faut abandonner la création de catégorie en cours pour aller créer un dossier ailleurs. → bouton « + Créer un dossier » directement dans le picker.

**Alertes multi-choix utilisées comme menus contextuels sur desktop** (impact moyen, effort faible)
`categories.tsx:156-178,224-245,247-261` : `showAlert` à choix multiples est correct sur mobile mais peu naturel sur web/desktop (l'app cible aussi Electron). → menu déroulant ancré au bouton sur web/desktop.

**Confusion possible sur la visibilité publique des catégories/dossiers** (impact moyen, effort moyen)
`compte.tsx:148-210` vs `profile/[id].tsx:367-430` : le profil public ne montre jamais les catégories/dossiers (toujours privés selon `confidentialite.tsx:171`), mais rien ne le rappelle sur le mur de « Mon espace » où catégories et recettes publiques cohabitent visuellement. → petit badge « privé » sur les tuiles catégorie/dossier du mur.

// 4.4 🔐 Compte, réglages & connexion

**Pas de biométrie, inscription en un seul long bloc** (impact fort, effort moyen)
`app/login.tsx:288-386` : le formulaire d'inscription empile pseudo/e-mail/mot de passe/confirmation sans étapes, et aucune option Face ID/Touch ID n'existe pour déverrouiller une session déjà ouverte — pertinent pour un usage en cuisine, mains occupées. → `expo-local-authentication` pour le déverrouillage rapide, scinder visuellement l'inscription en 2 groupes (identité / sécurité).

**Mode invité sous-exposé** (impact fort, effort moyen)
`login.tsx:388-393` : « Continuer sans compte » est en petit texte tout en bas, alors que « Mon espace » présente le mode hors-ligne comme un fonctionnement normal et assumé (`compte.tsx:214,261`). → mettre les 3 choix (créer un compte / se connecter / continuer sans compte) à égalité visuelle.

**Pas de confirmation d'abandon sur les formulaires de catégorie** (impact moyen, effort moyen)
Même famille que le point recettes ci-dessus : `create-categorie.tsx:101-108`, `edit-categorie/[id].tsx:114-122`.

**Mode développeur activable par accident** (impact faible, effort faible)
`a-propos.tsx:82-90,235-270` : 7 taps sur le numéro de version l'active, sans utilité pour un utilisateur non technique. → masquer derrière un identifiant de build/canal bêta.

**Double zone cliquable sur les cases « allergie »** (impact faible, effort faible)
`gouts.tsx:111-127` : toute la ligne ET le `Switch` interne déclenchent la même action — source potentielle de double-déclenchement selon la plateforme. → `pointerEvents="none"` sur le `Switch` puisque toute la ligne est déjà cliquable.

// 4.5 🖥️ Ergonomie transverse

**Aucun raccourci clavier sur la version desktop (Electron)** (impact moyen, effort moyen)
`electron/main.js:217-222` : la barre de menu est volontairement supprimée (bon choix pour épurer l'interface), mais cela retire au passage tout raccourci clavier standard (Ctrl/Cmd+N nouvelle recette, Ctrl/Cmd+F recherche...). Sur une app qui cible explicitement le bureau (mise à jour manuelle soignée, aperçu d'impression maison), ce sont des attentes normales de productivité pour un usage clavier/souris. → ajouter des `globalShortcut`/gestion clavier côté renderer pour les actions les plus fréquentes (nouvelle recette, recherche, nouvelle liste), sans réintroduire de barre de menu visible.

// 🗺️ 5. Priorisation recommandée

Correctif à traiter en priorité, avant toute nouvelle fonctionnalité :
1. **Ajout à une liste de courses ignore les portions ajustées** (bug fonctionnel, effort faible, 4 points d'appel à corriger).

Gains rapides à fort impact (à enchaîner ensuite, effort faible) :
2. Libellés « categorie » non corrigés.
3. `notifications.tsx` hors du design system des réglages.
4. Recherche dans les réglages de « Mon espace ».
5. Réordonnancement manuel des catégories/dossiers (réutilise un mécanisme déjà écrit pour les recettes).
6. Sélecteur d'unité avec recherche.
7. Navigation directe entre étapes du mode cuisine.
8. Filtre par tag dans la recherche de recettes.

Chantiers à impact fort mais effort moyen, à planifier ensuite selon les priorités du projet :
9. Autocomplétion des ingrédients à la création de recette.
10. Confirmation avant perte de formulaire non enregistré (recettes + catégories).
11. Partage natif d'une recette / liste de courses.
12. Biométrie + refonte de l'inscription.
13. Mode invité mis en avant dès l'écran de connexion.
14. Actions groupées sur les catégories.
15. Glisser-déposer catégorie → dossier.
16. Recherche transverse dans les dossiers imbriqués.

Le reste (scan code-barres, dictée vocale, indicateur hors-ligne, raccourcis clavier desktop, swipe-to-delete...) est noté pour une itération ultérieure : impact réel mais effort plus important, à ne pas lancer avant d'avoir traité ce qui précède.
